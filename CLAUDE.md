# Instructions for Claude when integrating @cboyke/demotools

This file is shipped inside the published npm package so it lands in
`node_modules/@cboyke/demotools/CLAUDE.md`. If you're an AI assistant helping
someone wire this library into a demo, read this first.

## The single most common breakage: missing Tailwind content path

The UI components (`JsonViewer`, `JsonModal`, all chat components) ship as
**compiled JS** in `dist/` with Tailwind utility classes embedded as string
literals — `bg-black/60`, `bg-[#1e1e1e]`, `text-[#9cdcfe]`, `text-[#d4d4d4]`,
`text-[#ce9178]`, etc.

Tailwind only generates CSS for class names it sees during its content scan.
By default a consumer's `tailwind.config.js` scans `./src/**` only, so **none**
of the classes inside this package's `dist/` get generated. Symptom: the JSON
modal opens but has no dark backdrop, no syntax colors, and the JSON tree
appears to bleed through onto the page underneath.

### Required fix (Tailwind v3)

Add the dist path to `tailwind.config.js`:

```js
content: [
  './index.html',
  './src/**/*.{js,jsx,ts,tsx}',
  './node_modules/@cboyke/demotools/dist/**/*.js', // ← required
],
```

### Required fix (Tailwind v4)

Add to the project's main CSS file (the one with `@import "tailwindcss"`):

```css
@source "../node_modules/@cboyke/demotools/dist/**/*.js";
```

### After changing the config

Restart the dev server. Vite's hot reload of `tailwind.config.js` does not
always rebuild the PostCSS pipeline cleanly — a full restart is the reliable
fix.

### Verify

You can confirm the classes are generated by running this in the browser
console once the modal is open:

```js
[...document.styleSheets]
  .flatMap(s => { try { return [...s.cssRules] } catch { return [] } })
  .some(r => /\.bg-black\\\/60\b/.test(r.cssText));
// should be true
```

Or visually: clicking "View JSON" should show a dim full-screen overlay with a
dark `#1e1e1e` panel, search bar, Expand/Collapse/Copy buttons, and
syntax-colored tree (cyan keys, orange strings, blue booleans).

## Integration checklist

When asked to integrate `JsonModal` or any component from this package into a
consumer repo:

1. **Check Tailwind version** (`node_modules/tailwindcss/package.json`).
2. **Patch the content scan** per the section above (v3 vs. v4).
3. **Restart the dev server** (don't rely on HMR for this).
4. **Smoke-test** by opening the modal and checking for the dark backdrop.

If you skip step 1–3, the demo *will* ship broken styling. This has bitten
real consumers — don't repeat it.

## Module boundaries

| Import path                     | Use in                | Notes                            |
|---------------------------------|-----------------------|----------------------------------|
| `@cboyke/demotools`             | Client + server       | `JsonViewer`, `JsonModal`        |
| `@cboyke/demotools/chat`        | Client only           | Chat components, types, hooks    |
| `@cboyke/demotools/chat/server` | Server only           | Agent loop, route factories      |

Keep `chat/server` out of `'use client'` files — pulling it client-side
bundles the LLM driver into the browser.
